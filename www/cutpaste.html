Cut and Paste

fineline uses the common <Ctrl-X> and <Ctrl-V> keystrokes to cut or copy text, and <Ctrl-V> to paste it. It uses an in-memory buffer to store the cut/copied text. If your app has multiple fineline instances running (in separate windows, perpaps) then all instances will share a single cut/copy buffer, to allow you to copy text from one instance to another. This is all built into the library; you don't need to write any code to make this work.

But what if you want to copy text between applications? Most Linux terminals let you use the mouse to select text, and then middle-click to paste it. That's one option, but fineline offers alternatives. Spoiler alert: It has built-in defaults that usually work fine for making <Ctrl-X>, <Ctrl-V> and <Ctrl-V> cooperate with your GUI's paste feature too.

Copy and Paste Hooks

You can call fineline_paste_hook(copyfn, pastefn), passing it two functions: one to call after text has been copied for <Ctrl-X>/<Ctrl-V>, and one to call before <Ctrl-V>.

void copyfn(const char *txt) should make fineline copy txt to the GUI. The txt is a '\0'-terminated UTF-8 string.

const char *pastefn(void) should fetch the current copy/paste text from the GUI, and return it as a '\0'-terminated UTF-8 string. If no text is available, it should return NULL. If the text is received in a format other than UTF-8, then it should convert to UTF-8 before returning it. fineline will NOT free the memory returned by pastefn(); if pastefn() allocates memory for the string that it returns, then it needs to track that memory itself, and free or reuse it itself.

External Programs

If you don't want to link with the GUI libraries (and thus make your application unrunnable if the library isn't installed), then you can also tell fineline to run external programs. This is done via fineline_paste_cmds("copycmd","pastecmd"), where copycmd and pastecmd are shell command lines that communicate with the GUI. The copycmd should read the text from its stdin, and thne pastecmd should write the GUI's paste text to its stdout.

Both X11 and Wayland offer stand-alone programs for accessing their inter-process cut and paste features. If you don't call fineline_paste_hook() or fineline_paste_cmds(), then fineline will try to guess whether you're running X11 or Wayland, and if so then it'll arrange for those programs to be run when appropriate. X11 uses xclip for both copying and pasting, while Wayland uses wl-copy for copying and wl-paste for pasting. Those programs come standard with X11 and Wayland; you don't need to install them separately.

I want to emphasize: fineline will use those programs for GUI copy/paste automatically, unless you tell it otherwise.

To guess whether you're running X11 or Wayland, fineline examines environment variables. If it sees a $DISPLAY environment variable, then fineline assumes you're running X11; if $WAYLAND_DISPLAY, then it assumes Wayland. Otherwise it assumes there is no GUI, and cut/copy/paste will only share text within the process.
