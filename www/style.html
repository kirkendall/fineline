Display Styles

fineline uses a few simple callbacks to update the display after each keystroke. Some involve cursor motion, or inserting/deleting rows. Others draw the actual text in a given style.

The callbacks are all function pointers in the fineline_t data structure. For simplicity's sake, the basic fineline_alloc() function is bolstered by "wrapper" functions that initialize all of the pointers appropriately for a bare ANSI terminal (fineline_tty()) or an ncursesw application (fineline_wcurses_alloc()).

The Callback Functions

The fineline_t data structure contains function pointers for the following terminal-related actions. The list is kept as short as possible, to simplify interfacing with a new display environment.
NameArgumentsPurpose
before(fineline_t *fine)Optional. If used, this will be called at the start of line input, and may be used for detecting screen size, switch to application keypad mode, etc.
after(fineline_t *fine)Optional. If used, this will be called after a line has been input, and may be used to restore any settings that were changed by before()
up(fineline_t *fine, int delta)Move the cursor up delta rows. If delta is negative then move the cursor down instead. This will never move the cursor up above the top of the screen, though it may move the cursor one row past the bottom of the screen in which case the terminal should scroll upward.
left(fineline_t *fine, int delta)Move the cursor left delta columns. If delta is negative them move the cursor right instead. This will never be used to move the cursor off either edge of the screen.
scroll(fineline_t *fine, int delta)Insert delta rows into the screen, scrolling the lower part of the screen downward. If delta is negative, then delete rows and scroll the lower part of the screen upward instead.
home(fineline_t *fine)Move the cursor to the leftmost column.
clear(fineline_t *fine)Erase text from the cursor position to the end of the row.
text(fineline_t *fine, const char *style, const char *text, size_t size)Erase text from the cursor position to the end of the row.

The plain ANSI terminal interface doesn't really need to know which fineline_t the above functions are being called for. For ncursesw, though, it needs the fineline_t mostly for the window pointer.

Styles

The text styles are all identified by name, in a C string. Some names are built into the library but you can also define your own, mostly in the syntax coloring callback. The built-in style names are:
StylePurposeTypical attributes
promptThe input promptbold yellow
inputText typed by the user, without syntax coloringnormal
selectText selected via <Shift-Arrow>normal on blue
matchUnmatched ()[]{} charactersbold cyan
searchSearch prompts, for <Ctrl-F>, <Ctrl-R>, <Ctrl-G>, <Ctrl-K>magenta
completeName completionsdim
hintHints such as function argumentsdim
titleHelp's titlesbold
linkHelp's links to other help pagesunderlined
codeHelp's code or monospace text
strongHelp's bold textbold
varHelp's variable textitalic
outputAny text written after a line is enterednormal

Each style has a foreground color, a background color, and some boolean attributes. Colors are limited to normal, black, red, green, yellow, blue, magenta, cyan, and white. ("normal" is the terminal emulator's default foreground and background colors, typically black and white.) Attributes are bold, dim, italic, underlined, blinking, boxed, and strike. Not all terminal emulators support all attributes, and even if they're supported individually they might not work in combination.

Configuring Styles

You can assign the colors and other attributes of a style programatically. Users can also change them while entering a like via the <Ctrl-K> configuration keystroke.

For <Ctrl-K>, you should enter style=attributes at the prompt, exactly as if you were setting a fineline option. For example, "<Ctrl-K>prompt=green<Enter>" would change the prompt to green.

Config strings

Colors and other attributes are specified via a string containing boolean attribute names, foreground color names, and "on" followed by a background color name. The order in which the words appear doesn't matter. For example "underlined red" would give red text on a normal background with underlining.

Any boolean attribute that isn't mentioned in the string will be false (not used). If no foreground color is mentioned then "normal" is assumed. If no "on" background color mentioned, then "normal" is assumed.

Synchronizing With The Application's Settings

If your application has its own scheme for storing attributes, then we need a way to synchronize fineline's idea of the style attributes and your application. This is entirely optional! fineline can take care of its own settings.

Call fineline_config_hook() to arrange for your application's function to be called whenever a fineline option or style is is changed.

Going the other way, if your application's idea of the settings has changed then it should call fineline_config_set() to copy the change into fineline.

Saving Attributes

Every time fineline changes its options or style attributes, it writes all of them out to a file. That file is named $HOME/.config/fineline/fineline.conf unless you call fineline_config_name(name) to change it, in which case the file is named $HOME/.config/fineline/name.conf.

That file will be reloaded when fineline initializes itself (i.e., when the first fineline_t is allocated), or when fineline_config_name(name) is called. If your application also stores attributes and you want your application's attributes to override the reloaded ones, then you should call fineline_config_name(name) before your application loads its settings, and then use fineline_config_set(text) after it loads its settings.
